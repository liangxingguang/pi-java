## 0. 计分口径

- **能力单元**：一个可外部观察的行为承诺，例如 CLI 参数、slash 命令、工具、事件、配置键或 UI 组件。
- **对齐**：pi 与 pi-java 都有且行为相同，计 1。
- **存疑**：形状或语义有差、行为未核或仍待裁决，计 0.5。
- **缺失**：pi 有而 pi-java 没有，计 0。
- **权重**：3＝每轮对话主路；2＝每次会话或常用；1＝低频、边缘或内部；0＝非目标。

```text
加权完成度 = Σ(权重 × 完成系数) / Σ权重
```

权重不表示排期优先级。TUI 权重不因 web 是主要交互方式而下调。

## 3. 新基线计分规则

1. 七份地图逐行重测，旧“对齐”不能直接继承。
2. pi 删除项必须有删除提交或新锚点缺席证据，再按 R1 出分母。
3. R5 按消费链判断，不能按文件名整包排除共享主流行为。
4. map/04 的 MCP 粗单元与 map/07 的细单元只计一次。
5. D′ 与 E5-31 按扩展 UI 成员集合去重。
6. F 整块与细单元不重复扣分。
7. examples 的能力单元与整包验收规格只保留一个计分入口。
8. 每层新读数先记录在当层地图；全部层完成后才替换本表总读数。

## 4. 范围结论

- **R1**：已删除的 experimental harness、session-backends、旧 server/client/plugin 发布面和其他经证据确认的删除面。
- **R2**：只覆盖已批准的主流 Provider；新增长尾 Provider 不自动扩面。
- **R5**：codemode、durable、chord、pico3、micro 不做，不进分母。
- **pi-java 独有面**：web 和 SQLite 独立后端不虚构 pi 对照分母，只做行为与兼容验证。
